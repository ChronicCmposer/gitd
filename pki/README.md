# pki/ — gitd TLS mTLS PKI tooling

Generates and renews the browse-server **mTLS** certificate material (Phase 5
`internal/browse`, R4-Q8 / R5-Q6 / R7-Q5): a TLS CA, a server cert, a client
cert, and a revocation list. Everything is **ECDSA P-256 only**, with OU role
separation (`server` for the server cert, `device` for the client cert) for
audit.

CA custody is local-only per R3-Q4 / R12-Q7: the CA keys live in
`~/.ssh/gitd-ca/` (passphrase-less, 0600, gitignored) and never leave this
box. The `pki/` staging tree holds the issued upload set destined for SSM and
is regenerated by the scripts here; the generated keys/certs/CRLs are
gitignored (see `pki/.gitignore`), while the scripts and `systemd/` units stay
committed.

Cert lifetimes (plan decision table): **TLS server 90d, client 30d, CA 10y**.

## Files

| File | Purpose |
|------|---------|
| `pki-new.sh` | One-shot bootstrap: TLS CA (10y) + server (90d) + client (30d) certs + CRL. |
| `issue-device-cert.sh` | Repeatable per-device TLS client cert (30d) + Apple `.mobileconfig` under `~/.ssh/gitd-device-certs/`. |
| `renew-server-cert.sh` | Client-side server-cert renewal (90d) + push to SSM (R12-Q6). |
| `gitd-cert-sync.sh` | **Host-side** (Phase 7): pull SSM `/gitd/server/*` → `/etc/gitd/tls/` (root, hourly). |
| `lib.sh` | Shared fail-fast helpers. |
| `systemd/` | Client-side renewal timer (`gitd-tls-renew.{service,timer}`). |

## Layout

```
~/.ssh/gitd-ca/
  tls-ca.key        TLS CA private key (0600, gitignored)
  tls-ca.crt        TLS CA cert (10y, P-256, OU=ca)
  tls-db/           CA index database (revocation tracking) + openssl.cnf
pki/                staged upload set (gitignored keys/certs/CRLs)
  server.crt        server cert (90d, OU=server, CN=git.cmposer.cc)
  server.key        server private key (0600)
  client.crt        client cert (30d, OU=device)
  client.key        client private key (0600)
  client-ca.crt     = copy of tls-ca.crt (the client trust pool)
  revoked.crl       CRL signed by the TLS CA
```

## SSM parameter paths (Phase 7 consumes these)

Pushed by `cloudformation/upload-certs.sh` (SecureString, default aws/ssm key,
R5-Q8) and pulled by the host `gitd-cert-sync` timer:

```
/gitd/server/server.crt
/gitd/server/server.key
/gitd/server/client-ca.crt
/gitd/server/revoked.crl
/gitd/host/ssh_host_ed25519_key
/gitd/host/ssh_host_ed25519_key.pub
/gitd/host/ssh_host_ed25519_key-cert.pub
```

Phase 7's userdata installs `server.crt`, `server.key`, `client-ca.crt`,
`revoked.crl` to `/etc/gitd/tls/` (root:root 0600/0644 per R6-Q5), matching
the `tls:` block in `configs/gitd.yaml`.

## Bootstrap

```
pki/pki-new.sh                      # generate CA + server + client + CRL
cloudformation/upload-certs.sh      # push /gitd/server/* + /gitd/host/* to SSM
```

## Issuing a device cert

Each browser/device that must talk to browse over mTLS gets its own client cert.
Run the helper (repeatable per device) against the local TLS CA:

```
pki/issue-device-cert.sh macbook
```

It emits, for the named device:

```
~/.ssh/gitd-device-certs/<device>/
  <device>.key            ECDSA P-256 private key (0600)
  <device>.csr            certificate signing request
  <device>.crt            client cert (30d, CN=<device>, O=gitd, OU=device)
  <device>.mobileconfig   Apple profile: CA trust + device identity (0600)
```

The `.mobileconfig` bundles the TLS CA (the client trust pool) and the device
identity (a PKCS#12) into a single install. The p12 is built from the freshly
issued cert with the maximally-compatible `PBE-SHA1-3DES`/`sha1` MAC options so
Apple's `SecKeychainItemImport` accepts it; its password is **auto-generated and
never written to a sidecar file** — it lives only in the shell and inside the
`.mobileconfig`. The intermediate `<device>.p12` is an input to the profile, not
a deliverable, so it is **shredded on exit**; only the key, cert, and
`.mobileconfig` remain.

**Treat the `.mobileconfig` itself as a secret** — Apple's profile format stores
the p12 password in plaintext inside it. AirDrop it to the device, install, then
delete it.

The cert is signed with the CA's `device_ext` (clientAuth EKU), then verified to
chain to `tls-ca.crt`. Device certs live under `~/.ssh/gitd-device-certs/`
(outside the committed `pki/` tree, which is the server upload set) and are
gitignored with the CA.

The browse server's client-CA trust pool **is `tls-ca.crt`**, so a freshly
issued device cert is accepted with **no server-side change**. To revoke a
device, reissue the CRL from the CA and push `/gitd/server/revoked.crl`.

## Renewal flow (R12-Q6)

Client-side monthly timer (`gitd-tls-renew.timer`, replace `__REPO_ROOT__` in
the unit) runs `renew-server-cert.sh` → re-issues the server cert + CRL →
pushes to SSM. The host-side `gitd-cert-sync` timer (Phase 7) pulls it to
`/etc/gitd/tls/`; browse re-reads every file per handshake, so rotation is
zero-downtime with no restart. The annual SSH host-cert renewal rides
`update.sh` via `ssh-ca renew`.
